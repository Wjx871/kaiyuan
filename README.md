# 开源软件社 · 社团嘉年华 · Hextris 定制版

一个挂在社团自有服务器上的开源小游戏，手机扫码即玩。
**玩完还可以提个点子：无需账号，在手机上体验一次模拟提交 Pull Request。** 愿意继续了解的同学，也可以给这个真实的开源项目贡献代码。

> 在线体验：<http://139.199.7.33/>

相关文档：[贡献指南](CONTRIBUTING.md) · [更新记录](CHANGELOG.md) · [部署说明](deploy/README.md)

---

## 怎么玩

1. 手机扫摊位上的二维码
2. 手指在屏幕左半边或右半边滑动，旋转中间的六边形
3. 让落下的方块三个同色碰在一起消除
4. 自由游玩，不设计时挑战；超过现场最高分后，请志愿者核实并领取奖励

不需要下载、注册或安装任何东西。

> 游戏里的最高分保存在当前浏览器中，各手机之间不共享。领奖以志愿者核实的现场纪录为准。

## 玩完，提个点子

1. 游戏结束后，点击 **「提个点子，体验 PR →」**
2. 在模拟页面里，输入你想改进游戏的点子（一句话即可，最多 300 字）
3. 点击 **「提交 PR（模拟）」**，查看你的点子与模拟提交结果
4. 点击 **「返回游戏，再玩一局」**，或再提一个点子

全程用手机完成，不需要电脑、GitHub 账号或编程基础。

这是纯前端模拟：内容仅在本次页面显示，不上传 GitHub 或服务器，不会自动上墙，刷新页面后会清除。真实 PR 通常包含代码修改，由维护者审核并决定是否合并；只有点子时也可以先提 Issue。

## 想继续参与真实开源贡献？（可选）

以下是需要 GitHub 账号的真实贡献流程，作为可选进阶体验，不影响前面的试玩与模拟提交。

### 第 0 步：准备一个 GitHub 账号

已有账号的同学可以直接登录；没有账号也可以先完成模拟体验，之后再到 <https://github.com/signup> 注册。

### 第 1 步：Fork 这个仓库

在页面**右上角**点 **Fork** 按钮，再点 **Create fork**。

这一步的意思是"把整个项目复制一份到你自己名下"。你现在拥有一个完全属于自己的副本，怎么改都不会影响别人——**这就是开源协作的底气**。

### 第 2 步：改一行配置

1. 在你自己的副本里，点开文件 **`carnival.config.json`**
2. 点右上角的**铅笔图标**（Edit this file）
3. 把 `slogan` 引号里的字改成你想写的

```json
{
  "slogan": "开源软件社 · 2026 社团嘉年华",
  "subtitle": "玩完提个点子 · 无需账号",
  "accent": "#4099ff"
}
```

三个字段都能改：

| 字段 | 作用 | 注意 |
|---|---|---|
| `slogan` | 游戏页面左下角显示的主标语 | 建议 20 字以内 |
| `subtitle` | 副标语，接在主标语后面 | 建议 25 字以内 |
| `accent` | 标语前那个小圆点的颜色 | 十六进制色值，如 `#4099ff` |

> ⚠️ **只改引号里面的内容**，别动引号、逗号和花括号。改坏了也没关系——仓库配了自动检查，会直接在页面上标红告诉你哪里错了。

### 第 3 步：提交 Pull Request

1. 改完后往下滚，找到 **Commit changes** 区域
2. 在描述里随便写一句，比如 `改个标语`
3. 选择 **Create a new branch for this commit and start a pull request**
4. 点绿色的 **Propose changes**
5. 下一页点 **Create pull request**

**恭喜，你已经提交了人生第一个 Pull Request。** 🎉

志愿者审核通过并合并后，服务器会在 1 分钟内自动更新——**刷新游戏页面，左下角就是你写的那句话。**

## 关于这个项目

### 技术结构

```
carnival.config.json    ← 你改的就是这个
carnival.js             ← 定制层：读配置、渲染标语、隐藏失效的外链
pr.html                 ← 手机端极简模拟 PR 体验，不上传输入内容
index.html              ← 入口
js/ style/ vendor/      ← 游戏本体
wall.html               ← 贡献者墙
contributors.json       ← 贡献者名单（由 CI 自动生成，别手改）
.github/workflows/      ← 自动检查与自动部署
```

`carnival.js` 的设计原则是**只做加法**：全程 `try/catch`，且不碰游戏本体逻辑。**即使配置文件被写坏，游戏也照样能正常玩**——这是为了活动当天不出事故。

### 部署方式

站点部署在社团自有服务器上（Windows Server + IIS）。服务器每分钟自动检查仓库有没有更新，有就下载并替换站点文件。所以**你合并的 PR 会在 1 分钟内自动上线**，不需要任何人手动操作。

部署脚本与说明都在 [`deploy/`](deploy/) 目录里——想学自动化部署的同学可以先读[部署说明](deploy/README.md)，再看源码。
